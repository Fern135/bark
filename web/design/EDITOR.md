# Bark editor

## Live workspace editing

Signed-in users can invite collaborators through the header. Shared workspaces
support simultaneous Python editing with automatic text merging and local undo;
independent Blockly stacks and world objects retain per-resource leases. Camera
frusta and colored name labels show teammates' camera locations, and outlines
show their selections. Moving, rotating or resizing an object is previewed on
peers before release, then saved through the existing durable commit path.
Presence and previews never enter exported games. Offline editing pauses and
reconnect catches up without replacing teammates' work. Play sessions remain
local simulations. The older preview-only notes below describe earlier UI work.

`/editor` implements the Code, Design, Viewport, add-object, gallery, and customization references. The homepage has an Open editor link. The existing homepage demo remains available.

## Run

Install dependencies once in `engine/`, `scripting/`, and `web/` with `npm ci`. Run `npm run dev` in `web/`, then open `/editor`. The predev/prebuild task compiles the two local packages and copies Havok, the scripting worker, and pinned Pyodide files into `web/public/runtime/`. Generated runtime files are ignored by Git.

The editor uses the engine's public API and the scripting package's compiler, adapter, and codec. The blocks entry now exports its registered `Blockly` instance so a host does not inject a second, unregistered copy. The Code view uses a Bark Blockly renderer, a persistent searchable palette with an icon rail, and CodeMirror. The editor shell, Scene panel, inspector, gallery flow, and model studio are separate components.

## Behavior

- Code edits one world script using real Blockly or Python. Converting retains a blocks backup; restoring warns before replacing Python edits.
- Design edits names, primitive colors, uniform size, and collision settings around an isolated orbitable model studio. Numeric transforms are in Viewport. Rotation is displayed in degrees and saved as a quaternion. Character capsules must remain solid and upright; engine validation reports incompatible edits.
- Viewport is a real Babylon/Havok world. Right drag to orbit, middle drag to pan, scroll to zoom, and select objects in the viewport or Scene. The starter character uses WASD/arrows and Space when Play has canvas focus.
- The starter catalog contains locally served GLBs and a primitive ball. Seven rounded project meshes are generated by `scripts/prepare-toy-models.mjs`; remaining models use the licensed Kenney assets documented in `public/models/starter/README.md`. Thumbnails are rendered from the same assets used in the editor.
- Add object supports category selection, search/filter, custom name/size, and validated self-contained GLB uploads. GLB objects initially use simple box colliders, or a capsule for characters. The model can be orbited in the gallery before adding.
- Import/export use version 1 `{ version, project, script }`. Exports embed declared assets. Changes during Play are temporary; Stop restores authored defaults. Save labels refer to a local file download, not cloud storage.
- Editing is locked during playback and file operations. Unsaved work warns before page exit or project replacement. Narrow layouts move Scene and settings into dialogs.

The top-right collaborator control shows three separate circular avatars in a horizontal row and opens a UI preview with sample members (You, Alex, and Sam), roles, and presence. It uses a keyboard-accessible popover and a disabled invitation action. The Preview label in the menu identifies the sample data; no collaboration requests, account lookup, persistence, or export fields are added. It remains available during playback and in all editor views.

Preview captures: [desktop](editor-collaborators-desktop.png) and [mobile during playback](editor-collaborators-mobile.png). The focused browser checks are in `tests/collaborators.spec.ts`.

Live collaboration, invitations, publishing, cloud saves, per-object scripts, extra languages, model animation controls, and browser recovery are deferred.

## Rendering and compatibility

`runtime.cameras.frame(id?, padding?)` fits either an object subtree or the world without changing the authored document. Model loading waits for render readiness, so thumbnails do not capture uncompiled models. Studio scenes own their camera, lighting, pedestal, canvas, and runtime; they dispose on changes/unmount and are never exported.

JSON remains version 1. Legacy primitive games still import, edit, and reset safely. Import disables editing/Play while parsing embedded assets, preventing playback of the previous script during an import. Static model thumbnails avoid creating a second rendering runtime on a normal page load.

Run `node scripts/render-catalog.mjs http://localhost:3000` from `web/` to regenerate thumbnails after changing model artwork. Model licensing and the reproducible conversion command are documented with the assets.

## Object transform tools

The viewport toolbar provides Select (1), Move (2), Resize (3), and Rotate (4). Move uses axis arrows and plane handles; Rotate uses rings around the entity pivot. Resize uses six face handles around visible subtree bounds, anchored to the opposite face. Alt anchors resizing at the bounds center and Shift preserves proportions. Characters stay upright and resize uniformly; sphere/capsule colliders and parents with children also retain uniform scale.

Transform settings contain World/Local orientation, snapping (0.5 units movement, 0.25 units resize, 15 degrees rotation by default), Focus object (F), and Reset view. Resize always follows local axes. Escape, pointer cancellation, leaving the canvas, window blur, tool changes, and playback cancel active drags. Right drag orbits, middle drag pans, and the wheel zooms. Shortcuts ignore text fields, code editors, and dialogs.

`GameRuntime.editorTools` is opt-in and exposes configure/get/cancel. The engine owns Babylon utility-layer handles and emits editorSelection/editorTransform events. A validated presentation transaction updates the visible node without rebuilding Havok bodies or modifying authored exports; commit restores the starting node and applies the completed transform through the existing world API once. Editor meshes never become project entities. Rendering runtimes that do not opt in retain their camera behavior.

The inspector follows previews without exporting the project or rebuilding Blockly choices on every pointer movement. Transform undo/redo (Ctrl/Cmd+Z, Ctrl/Cmd+Shift+Z or Ctrl+Y) records one completed handle drag or numeric edit, with a 100-entry limit. History survives Play/Stop and clears when projects are loaded or non-transform scene edits are made. All state is local to the frontend; project JSON remains version 1.


## Viewport properties panel

Viewport uses a left Properties column, the live canvas, and a full-height Scene column. The former bottom-right Transform card is removed. Properties shows the selected thumbnail, name, type, and one open section: Transform (default), Appearance, or Collision. Shared Inspector fields retain existing project mutations and transform history; Appearance adds visibility without clearing selection. Numeric scale edits honor the 0.01 minimum and proportional constraints; character X/Z rotation and child collision editing are disabled with explanations. No selection shows World settings. Playback locks property edits.

At widths of 1180px and above both side panels remain visible. From 951-1179px Properties stays on the left and Scene uses its drawer; at 950px and below both use named drawer buttons. Accordion content, density adjustments, and a pinned Delete action keep the panels within the viewport without scrolling. Motion animates section changes and selected-object identity, respecting reduced motion. Code and Design retain their layouts.

Validation covers property edits, visibility and collision persistence, transform undo, scale restrictions, model-gallery access, deletion, playback locking, desktop bounds, tablet selection, mobile drawers, and canvas-relative handle dragging.
